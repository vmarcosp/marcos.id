The snippets on this site are the ones I reach for while working. A shell function. A conversion. Something I can paste and leave. They get worse when I try to turn them into an essay, so I stopped doing that.

This page is the other pile. A note that needs a paragraph to set up, and another to say the thing. Still plain. Still something I would send to a friend who asked.

## What lands here

A piece belongs here when it is about the work, and when a snippet would have to pretend it is shorter than it is.

- How a tool feels after a month, not the install command.
- A decision I would make again, and the constraint that forced it.
- Something I keep explaining in chat and should just write down.

Release notes, and a list of links with no point of view, can stay where they are.

> Keep the command in the snippet. Keep the reason here.

If a note can live in one fenced block, it stays a snippet. `mktouch` is one of those:

```sh
mktouch src/path/to/component/Component.js
```

The rest can take the long way. The short ones are still on [Snippets](/studio/snippets).
